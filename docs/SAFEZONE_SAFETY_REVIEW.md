# SafeZone — safety and privacy review

**Verdict: safe to keep merged behind the off-by-default flag. Not safe to enable for real children** until the release gates in §4 close.

## 1. FAMILY.md "safe enough to ship" checklist

| Question                                                       | Answer                                                                                                                                                              | Evidence                                                                                       |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Child access scoped to own household, server-side **and** RLS? | Yes. Child commands require this household's active explorer. Raw tables are household-private. Cross-household reads are sanitized functions.                      | DB: isolation, foreign-child tests. E2E 5 (API + direct PostgREST with another guardian's JWT) |
| Interaction between children structured, not open-ended?       | Yes. Children can only choose moderator-authored cards. No free-text field exists in schema, API, or UI.                                                            | Schema; validation schemas accept only an `option` id                                          |
| Guardian-visible, honest record?                               | Yes. Registration, withdrawal, removal (with reason), closure, and report updates notify the household. History lists every session.                                | DB + E2E 11                                                                                    |
| Reportable, with an auditable case?                            | Yes. `safezone_reports` + append-only `safezone_report_events`. Removal and emergency closure create incidents automatically.                                       | DB report test; E2E 10                                                                         |
| Anything identifying a child outside the household?            | No. Peers and moderators see only per-session handles. Questions carry no handle. Room payloads are asserted not to contain nicknames, child ids, or household ids. | DB room-leak test; E2E 7 (`Nova` absent from peer page)                                        |

## 2. Brief's non-negotiable safeguards

| Safeguard                                                             | Status                                                                                                                                                                                      |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Verified guardian consent appropriate to age/law                      | **Partial.** Per-session consent + password re-authentication enforced in the DB via the `amr` claim. _Verifiable parental consent_ (COPPA-grade) is a legal/program decision. **BLOCKED.** |
| No private messaging (child↔child, adult↔child)                       | **Met by construction.** No messaging table, endpoint, or field. Moderators act through cards, turns, approvals, polls, and recorded removal reasons only.                                  |
| Trained, authorized human moderators                                  | **Technically enforced** (staff role, operator-granted; per-hall assignment). Training/vetting/DBS-style checks are an operational process. **BLOCKED.**                                    |
| No public display of names, locations, contacts, schools              | Met: handles only; no location/school fields exist.                                                                                                                                         |
| Age-banded sessions, server-side permissions                          | Met: band checked in the DB at registration; archived explorers refused.                                                                                                                    |
| Reporting, immediate removal, escalation, audit logs                  | Met: in-room reports; removal with reason; emergency closure escalates an urgent incident; all commands audited.                                                                            |
| No livestreams/recordings by default                                  | Met: no media capability exists.                                                                                                                                                            |
| AI moderation with human review; no autonomous safeguarding decisions | Met by absence: no AI in the path. Every approval and decision is a human command.                                                                                                          |
| Data minimization, retention, COPPA review                            | **Partial.** Minimal fields; withdrawal erases contributions and votes; deletion cascades. A retention schedule and legal review are **BLOCKED**.                                           |

## 3. Threats considered

| Threat                                                                     | Mitigation                                                                                                        | Residual                                                                                                                                                                           |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Child self-consents on the guardian's signed-in device                     | Password re-entry + DB-side `amr` < 5 min                                                                         | For 5 minutes after the guardian consents, the device session can register further sessions. Mitigation: shorten the window, or require a password per request (no session reuse). |
| Other household reads/acts on my explorer                                  | Ownership in the API (`ownsChild`) and the DB; RLS; sanitized reads                                               | —                                                                                                                                                                                  |
| Peer de-anonymization                                                      | Random handle per hall; questions anonymous; no nickname leaves the household                                     | Handles are random within a hall but the same explorer across halls gets a different one (good). Small rooms make inference easier; set minimum capacity policy.                   |
| Spam/flooding                                                              | 5s per-explorer rate limit, 20 contributions/hall, de-duplication, 10 reports/hour                                | No app-level IP rate limit (project-wide open item)                                                                                                                                |
| Bullying through card choice (e.g. repeatedly endorsing a hurtful framing) | Moderator writes all cards and approves each use; removal with reason; reports                                    | Depends on moderator content quality, which needs content guidelines                                                                                                               |
| Moderator misconduct                                                       | Moderators see handles only, never nicknames or household ids. Every action audited. Moderation notes staff-only. | Needs two-adult rule and audit review process (operational)                                                                                                                        |
| Rogue staff grant                                                          | Staff role grantable only by SQL (no app path)                                                                    | Operator access control is out of repo scope                                                                                                                                       |
| Withdrawal leaves traces                                                   | `sz_release` marks contributions `withdrawn` (hidden from all reads) and deletes votes                            | Audit rows record that commands happened (no content)                                                                                                                              |

## 4. Gates before enabling for real children

1. Legal review: verifiable parental consent, COPPA/UK AADC/GDPR-K as applicable, retention schedule, cross-border participation.
2. Moderator program: vetting, training, two-adult rule per session, escalation contacts, incident SLA.
3. Content guidelines for card authoring, plus a second-person review of drafts before publishing (`draft → scheduled` is currently a single moderator action).
4. Hosted certification: run both E2E suites against the hosted stack; Supabase advisors; load test with 30-seat rooms.
5. Decide whether to amend `FAMILY.md` §2 for free text. If so, design PII screening and human pre-publication review first.
