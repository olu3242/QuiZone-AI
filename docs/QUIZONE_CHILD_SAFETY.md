# QuiZone AI — child safety controls (platform-wide)

`FAMILY.md` is the charter and outranks every other document. This file maps its rules to the controls that implement them across all zones. SafeZone-specific detail: `SAFEZONE_SECURITY_MATRIX.md`, `SAFEZONE_SAFEGUARDING_CHECKLIST.md`.

| `FAMILY.md` rule                                                     | Control                                                                                                                                                                                                       | Zones              | Proven by                                   |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | ------------------------------------------- |
| §1 Guardians accountable; access scoped                              | Only confirmed guardian accounts act. Children have no credentials. Every command checks household ownership in the API and the DB. RLS on every table.                                                       | All                | DB suites; E2E F8, S5                       |
| §1 No child-to-child interaction outside guardian-enabled structures | WorldZone and SafeZone each need a guardian permission. SafeZone also needs per-session consent with a fresh password.                                                                                        | World, SafeZone    | DB; E2E S3, S4                              |
| §2 No unrestricted messaging                                         | No messaging table, endpoint, or free-text field aimed at another user, anywhere. Debate and SafeZone use fixed stages and moderator-authored cards. **Owner decision 2026-11-01: SafeZone stays card-only.** | All                | Schema review; validation schemas           |
| §3 Data minimization                                                 | Nickname (charset-limited) and age in years only. No school, address, or contact fields. Cross-household views use per-session handles or aggregates.                                                         | All                | DB room-leak test; E2E S7                   |
| §4 Age-appropriate by construction                                   | Age band checked server-side at game creation and SafeZone registration. Content needs an explicit age review before publishing.                                                                              | All                | DB; E2E S3                                  |
| §5 Q has a narrow role                                               | Curated, reviewed hints only; permission-gated; 10 per session; every output logged                                                                                                                           | Q                  | DB                                          |
| §6 Moderation is a real system                                       | `moderation_cases` (games) and `safezone_reports` + append-only events, with reviewer, status, and timestamps. Removal and emergency closure create incidents.                                                | Games, SafeZone    | DB; E2E S10, S11                            |
| §7 Access-controlled storage                                         | No media uploads exist; no public buckets                                                                                                                                                                     | All                | —                                           |
| §8 Public site discipline                                            | The landing page carries marketing copy only; internals live in `docs/`                                                                                                                                       | Landing            | Review                                      |
| Consent withdrawal                                                   | Turning a permission off withdraws participation; SafeZone withdrawal erases contributions and votes                                                                                                          | World, Q, SafeZone | DB; E2E S14                                 |
| Account / child deletion                                             | Deletion cascades through every zone, plus a ledger entry with no identifying data                                                                                                                            | All                | DB family-controls, safezone 16–17; E2E F15 |
| Abuse resistance                                                     | Rate limits on commands, password re-verification, and export; contribution and report caps                                                                                                                   | All                | DB hardening; E2E R6                        |

## Not yet satisfied (blocks real children)

- Verifiable parental consent (legal); approved age bands (8–17 is a placeholder)
- Moderator vetting and training program; a two-adult rule enforced in software
- Retention schedule; whether safety records survive account deletion (legal)
- International privacy review before cross-household WorldZone
